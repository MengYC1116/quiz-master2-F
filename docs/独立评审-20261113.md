## 1. 产品定位与用户价值

**结论：定位是全项目最强的部分，也是最诚实的部分。**

**优点**

- 目标用户单一且明确：单个大学生，个人使用。基线（01 §1）用一整节写“明确不是什么”（不是教师/学校/班级/多用户/Web），并在 11 月 11 日从“全能题库”收窄到“以错题管理为核心的错题本”，这个收窄是正确的——通用题库拼不过粉笔、猿题库，个人错题管理才有生存空间。
- “治错因，不背题”是真正的产品思想，不是口号。11 月 12 日负责人一句话否决翻卡 + 间隔重复（“考试不会再出原题，背题没用”），换成按错因治疗的四步模型，这是全项目最有价值的一次决策，且已完整落地为代码（`review_page.dart`、错因三态、治愈需两次自查、复查机制）。
- 主轴与延伸价值分得清：收集/整理/分类/搜索/管理是主轴，复习与报告是延伸，不喧宾夺主。

**问题**

- “智能”二字名不副实。产品名叫“个人智能错题本”，但现有的“智能”只有 YOLO 框题——而 YOLO 至今是占位（见第 2 节）。没有 OCR（有意为之）、没有解析推荐、没有同类题推送。卖点实际是“自由 + 隐私 + 离线”，不是“智能”，文案上宜诚实，不要透支“智能”这个词。
- 定位高度依赖“用户自己有卷子”。收集是唯一入口（无手动录题、无题库内容），而收集链路恰恰是最不成熟的一环（第 2 节）。冷启动成本全压在用户身上。
- 学段绑定较死：三科预设（数学/英语/政治）与大学级知识点树写死在种子数据里，换学段（如高中）要重做种子与树，不是改个配置。

**建议**：对外介绍改称“离线个人错题本”，把“智能”留给 YOLO 接入之后再说。

## 2. 功能完整性：九页是否闭环

**结论：UI 层闭环，业务层约三分之二真实；最核心的链路恰恰是假的。**

**已真实实现**（有代码、有测试、有截图）：九页导航与外壳、整理工作台（H 布局 + D 队列弹窗 + 批量）、错题本（书架 → 目录 → 列表、文件夹树、批量、分页 UI）、题目详情（三段折叠、编辑、脏检查）、复习四步会话与总结、学习报告（纯数字文字）、学科管理四段、设置五组、演示数据与一键清理。

**占位 / 未验证**（证据在 R11 §8.3、交接文档、代码抽查）：

| 项 | 证据 |
|---|---|
| 真实 YOLO | `yolo_onnx_service.dart` 仍是占位：`hasRealModel` 恒 `false`，每页只返回一个写死的整题框（x 0.06 / y 0.05 / w 0.88 / h 0.85），无第 2 层框；默认模型路径 `assets/models/best.onnx` 根本不存在；全库唯一一个 `TODO` 就是这里（D-07） |
| 真实图片切片 | 切片是 `QuestionSlice` / `_SliceFigurePainter` 的示意绘制，不是按框裁原图的真实字节 |
| 系统拖放导入 | 只有诚实占位文案“拖放导入还没接好”；接拖放需新增依赖，超出当前边界 |
| 导入进度 | Timer 模拟的百分比，不是真实解析进度 |
| 加密 PDF 判定 | 启发式（文件头 `/Encrypt`），不是严格判定 |
| 分页翻页 | 只在 widget 测试（12 道假题）里覆盖；真实库每科 2–3 道题，只有一页，从未实测 |
| 修框全流程 | 无真实文件可导入，拖动/改大小/重画/双击内框整条链没在真文件上跑过 |

**缺口评估**：缺口不在“多”，而在“关键”。收集 → 框题 → 切片是产品的第一公里，也是用户第一次使用的链路，至今没有任何真实验证。九页里其余八页做得再好，用户第一步就可能卡住。好消息是模型文件今天已到（两个 `.onnx`，各约 38MB），YOLO 接入已排进队列，缺口有望在近期补上。

## 3. 设计与体验

**结论：视觉统一且有辨识度，是项目第二强的部分；剩余问题多是细节与平台差异。**

**优点**

- 主题有性格：极简 × 专业 + 年轻学习伙伴感（亮蓝主色、圆角、每科一色），与 11 月 10 日“风格太通用”的教训形成对比；唯一签名元素（学习小伙伴形象）只出现在空状态与首页，克制得当。
- 一致性有证据：HTML 原型 SHA256 锁定为视觉基准，33 张 HTML/Flutter 并排对照图，322 张截图存档；R11 抽查三张对照图结构/样式/文案一致；亮/深双主题 + 三档字号（1.00/1.15/1.30）每页都有截图与测试覆盖。
- 文案与空状态做得细：删除统一“删了就没了，确定吗？”，未填字段如实显示“待补充”，各页空状态都有小伙伴 + 一句话 + 去处按钮。

**问题**

- 全部视觉结论都在 Linux 回退字体（Noto Sans/Serif CJK）上得出，Win11 的 Segoe UI / Microsoft YaHei / Georgia 尚未验证。已知差异已出现：导航学科速览在 Linux 下换两行（回退字体偏宽），按字宽估算 Win11 应为一行——这是估算，不是验证。
- 细节债务仍在收尾：导航选中 pill 间歇纯白（R11 深色复习页复现一次；Win11 实机黑 pill 已修并回归通过）；放大浮层 1.5× 偏移在 §8 A1 刚修完；弱点并列行是码点排序而非中文拼音排序（Dart 无拼音排序），只影响并列先后。
- 一处有意的偏差：题目详情是推送全窗路由、无左导航，而 HTML 原型里详情在壳内带左导航（基线架构所致，R7 已记录）。

**建议**：Win11 验收时先看字体与导航两处，不要只看页面能不能打开。

## 7. 风险与可持续性

**结论：最大风险不在代码，在“还没验证”和“只有一个人能维护”。**

| 风险 | 严重度 | 说明 |
|---|---|---|
| Win11 未验证 | 高 | R11 §9 列了 8 项：字体、窗口尺寸、DPI、SQLite 原生资源、Windows Release 构建、两个同名模型、onnxruntime 版本、真文件全流程。Linux 结果不能替代，负责人须亲自在 Win11 上验收 |

| Bus factor ≈ 1 | 高 | 维护者是负责人本人，他不会 Dart；代码地图与 CODEBUDDY 是为他写的，但“读得懂地图”不等于“能改代码”，实际维护依赖 CodeBuddy 这类 AI 工具，工具换代或不可用时维护能力断崖 |
| 二进制模型进仓库 | 中 | 两个模型共约 76MB，Git 无 LFS；连接器推不上去，负责人需手动推。仓库会因此膨胀，且模型更新即新增大文件。应明确“模型不进 Git，用单独渠道分发”或上 Git LFS |
| 无 CI | 中 | analyze / test / build 全靠人工跑，回归依赖自觉。哪怕只上一条 GitHub Actions（analyze + test），也能防住“改 A 坏 B” |
| 版本锁定 | 低 | Flutter 3.47.9 / Dart 3.13.7 锁定是正确的短期选择，但长期不跟进会积累升级成本；建议每季度评估一次是否跟进一个小版本 |

## 8. 与同类产品的比较

（依据：公开资料检索，2026-11-13。粉笔、猿题库均为在线、账号制产品。）

| 维度 | 粉笔 / 猿题库 | quiz-master2 |
|---|---|---|
| 内容来源 | 海量自有题库（粉笔 240 万+道公考题；猿题库覆盖初高中真题与模拟卷） | 无题库，内容全靠用户自己导入 PDF/图片 |
| 错题归集 | 做题自动收录，按知识点自动归类；可一键重组错题试卷 | 手动导入 + 手工整理；文件夹/标签自由组织，不自动归类 |
| 复习方式 | 按知识点推送同类题、AI 智能组卷、错题重练 | 按错因四步治疗，不推送新题，不背原题 |
| 解析 | 官方解析、视频精讲（部分付费） | 无解析来源，答案/解析全靠用户手填 |
| 同步与设备 | 云端同步，多设备登录；猿题库明确“没有离线刷题功能”，须联网 | 完全离线本地，无账号无服务器；Windows 桌面，Android 待定 |
| 隐私 | 题目与学习数据在厂商服务器 | 数据只在本地 SQLite，隐私是卖点之一 |

**差异化判断**：本项目的差异化不在“更智能”，而在三个点——（1）**自己的卷子**：任何来源的试卷、作业都能进，不限于平台题库；（2）**按错因治**：市面产品多是“重做错题 + 推同类题”，本项目是“找到为什么错并治好它”，理念上更贴近负责人“考试不考原题”的判断；（3）**离线与隐私**：无账号、无云端，数据只在本地。这三点对“在意隐私、卷子来源杂、不想被题库绑住”的大学生是真实价值。

**不如别人的地方**：没有内容（冷启动最重）、没有解析（最影响使用体验——用户整理一道题要手填答案与解析）、没有跨设备、没有拍照搜题、没有 AI 推荐。诚实地说，现阶段本项目更像一个“做得很好的个人错题整理工具”，而不是“智能学习产品”。

## 9. 总体结论与优先级建议

**总体结论一句话**：设计与流程已达到可交付水准，真正的交付只差两件事——Win11 真机验收与 YOLO 真实链路——做完这两件才能说项目闭环。

### 必须做（不做等于没完成）

1. **Win11 真机验收**：字体、DPI、Windows Release 构建、SQLite 原生资源——Linux 结论全部是假设。
2. **接真 YOLO + 真切片 + 真文件全流程验证**：用真实试卷页跑完导入 → 检测 → 修框 → 整理 → 复习，含推理耗时记录。
3. **备份补 4 张表 + 数据库位置迁移旧库（B4.2/B4.3）**：否则备份与换位置都可能丢数据。
4. **做完 §8 剩余项（A4–A6、B 组）并回归**：已在进行中，不要中途换方向。
