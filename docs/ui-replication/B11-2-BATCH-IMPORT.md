## 行为

- 一次多选图片 / PDF 导入（文件选择器本身已支持多选；拖放多文件
  同走此流程，见 B11-1）。
- 导入队列：逐个处理（每张走现有 `enqueue`：复制进库 + PDF 整本渲染 /
  图片 EXIF 归一化；YOLO 检测仍在修框时跑，不在导入时跑）；队列卡片
  显示总进度与每行状态（排队中 / 导入中 x% / 已完成 / 失败+原因）；
  单张失败不影响整批；失败行可单独重试，也可“重试全部失败项”
  （只重导失败的，成功的与已在队列里的不动）。
- 自动去重（内容哈希 SHA-256）：与已入库任务内容相同（文件名不同
  也算）时，进既有“已经导入过”横幅，等用户点“仍然再导一份”才继续；
  用户确认重导后仍会建任务（不静默拦截）。同批内后出现的相同内容
  直接丢掉（只留第一份），并出 snack 告知。
- 按文件名猜学科 / 试卷：只做建议预填下拉框，绝不静默自动指定。
  学科：猜到才预填，并在下拉框下显示“按文件名猜是「数学」，不对
  可以改”，用户随时可改；本批猜得不一致、或有文件猜不出时不预填。
  试卷：只在队列行上显示一行“建议试卷：期中考试”，不写库；整理时
  仍由用户在整理工作台选 / 新建试卷。
- 现有单文件导入行为不变（不建队列卡片、不改任务行、不改确认横幅）。

## 决策（请协调员记 D-25+，未改 docs/decision-log.md）

- **去重口径：内容哈希 = 全文件 SHA-256**（`crypto` 3.0.8，纯 Dart，
  无原生依赖）。不做“文件名+大小”弱哈希：同名不同内容、同内容
  不同名都要分得清。口径依据是代码里的实际实现，不是 D-08
  （D-08 是整理工作台布局 H，与重复导入无关）；代码现状是：文件名
  命中 → 横幅警告、用户确认才重导；同批同路径 → `enqueue` 内静默
  跳过。本次只在文件名口径旁并列一条内容哈希口径，确认流程不变。
- **不改 Schema。** 哈希不入库，每次导入时按任务 `sourcePath` 现算
  已入库原文件的哈希；原文件缺失的任务无法验证，直接跳过（不误拦）。
  代价：任务很多时每次导入都要读一遍已入库原文件；个人题库量级可
  接受，后续如需优化再入库存哈希字段。
- **`enqueue` 本身不加哈希去重。** 同批内容去重放在收集页
  （`checkContentDuplicates`），`enqueue` 仍只做既有的路径去重——
  避免改动已有回归测试覆盖的核心导入路径。
- **队列语义：** 顺序逐个、失败不中断、重试只重导失败项。重试沿用
  本批学科（不重新猜）；队列卡片可关闭（只关卡片，不删任务）；
  新一批导入替换旧队列卡片；单文件导入不建队列。
- **文件名猜学科规则**（`import_guess.dart` 内有完整关键词表）：
  关键词命中取最长者，等长时按预设顺序 数学 / 英语 / 政治；
  自定义学科用学科名本身匹配；一批文件必须全部猜到同一学科才预填。
  关键词只列 2 字以上，避免单字误撞；英文关键词不分大小写。
- **文件名猜试卷规则：** 去扩展名 → 去日期（2026-03-15 / 2026年3月 /
  20260315）→ 按分隔符分词 → 丢纯数字词、“第 N 页 / 第 N 题”、
  学科关键词与通用词（试卷 / 错题 / 扫描 / 图片 …）→ 剩下 ≥2 字
  才作为建议。猜不出返回 null，不显示、不写库。
- **“没选学科也能先选文件”是 B11-2 的必要前置：** 以前选文件前
  必须先选学科，猜测永远没有触发机会。现在文件可暂存，等用户选好
  学科点“开始导入”再导；“没选学科不能导入”口径不变。

## 已知限制

- 内容哈希每次导入都要读文件：50MB 的 PDF 会多读一遍（哈希一遍、
  复制一遍），导入耗时略增，可接受。
- 试卷名猜测是启发式：文件名信息不足（如只有“数学.pdf”）时不猜，
  不会硬凑一个名字出来。
- 批量队列是内存状态：导入中途关掉应用，队列卡片消失，但已建的
  任务行（`collect_tasks` 表）不受影响，下次打开仍在列表里
  （与现有“队列重启后保留”口径一致，任务本身是持久化的）。
