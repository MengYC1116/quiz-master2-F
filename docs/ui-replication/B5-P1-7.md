# B5-P1-7：整理页打开队列层不保存当前表单，批量操作用旧快照覆盖丢改动（SR-P1-7）

## 结果

已修。打开队列层之前先把当前表单落盘，批量操作不再用打开时的旧快照
整行覆盖，表单里未保存的改动（文件夹、标签、答案、错因等）不会再被
静默抹掉。队列弹窗本身的交互不变：勾选状态仍只活在弹出层内，关闭即
丢弃；关闭、遮罩、Esc 关闭后重开仍为已选 0 道（既有测试继续通过）。

## 根因（比报告多走的一步）

报告建议的修法是“`_openQueue` 改成异步，先 `await _saveCurrent()` 再弹层”。
只这样做还不够：`_saveCurrent()` 只写库，内存里的 `_queue` 仍是打开前
的旧对象；弹出层拿 `List.of(_queue)` 拍快照，批量打标签 /
批量加文件夹 / 批量确认整理都用快照里的旧 `Question` 做
`repo.save(q.copyWith(...))` 整行覆盖——`Question.copyWith` 不传的字段
保持旧值，于是刚保存的文件夹、答案等一样会被写回旧值抹掉。
所以修复分两步，缺一不可：

1. `_openQueue` 改异步，先 `await _saveCurrent()` 再弹层；
2. 落盘后把刚保存的表单行写回 `_queue`（与 `_saveCurrent` 保存的是
   同一个 `_formQuestion(current)` 对象），再给弹出层拍快照。

单删（`_deleteOne`）是显式删除，不受影响，未动。

## 改动文件

- `lib/modules/organize/organize_page.dart`（`_openQueue`，唯一生产代码改动）
  - `void _openQueue()` → `Future<void> _openQueue() async`（`InkWell.onTap`
    是 `void Function()?`，返回 `Future<void>` 可直接挂，与 `_openDetail`
    同款用法）。
  - 开头仍先 guard（队列为空或层已开直接返回，不保存）；随后
    `await _saveCurrent()`，`if (!mounted) return;`。
  - 落盘后把 `_formQuestion(current)` 写回 `_queue` 中对应 id 的位置
    （`setState`），再继续原来的 Overlay 定位与 `List.of(_queue)` 快照。
  - 保存是异步的，等的过程中用户可能又点了一次「队列」，首道 guard
    拦不住第二次调用：保存后、插层前再 guard 一次，避免插两个层。
    （第二次调用的保存本身是幂等的，只是重复落盘一次。）
  - 队列弹窗（`_QueuePopup`）及其批量方法（`_batchTagRedo` /
    `_batchAddFolder` / `_batchConfirm` / `_batchDelete`）、`_closeQueue` /
    `_jumpToQuestion` / `_applyQueueSort` 均未动。
- `test/organize_page_test.dart`（新增 `SR-P1-7 打开队列前保存当前表单` 组，3 个测试）
  - 共用 helper `editCurrentForm`：给当前题 q1 选文件夹「平时作业」（f2）+
    填答案「答案：1」，只改表单 state，不点保存/确认；末尾把页面滚回
    顶栏（填答案时页面滚到底，「队列」按钮会滚出视口点不到）。

## 遗留问题

- 无本项遗留。顺带注意（未修，不属 SR-P1-7 范围）：`_saveCurrent` 只写库
  不同步内存 `_queue`，是本项根因的同一机制——`_jumpToQuestion` /
  `_goTo` 等切题路径保存后也不刷新 `_queue` 里刚保存的那一行；切走
  后再切回来时 `_loadForm` 读的是旧对象，表单可能显示旧值（库里是对的，
  再一切题或一刷新就恢复）。如需根治，应在 `_saveCurrent` 内统一把
  保存后的行写回 `_queue`，或切题时 `_refresh`；建议由协调员另立一项，
  不要随本项顺手扩大范围。
