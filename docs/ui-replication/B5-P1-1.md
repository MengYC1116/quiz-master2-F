# B5-P1-1：错题本封面三数与首页口径不一致（SR-P1-1）

## 结果

已修。封面三数沿用首页互斥拆分（已定口径），两处旧不一致均消除：

- (a) 纯复查题（全部错因已解决、但有一条到了复查时间）：封面“要复习”
  不再为 0——它只计“待复查”，与首页把它算进“要复习”总数一致
  （要复习总数 = 待解决 + 待复查）。
- (b) 混合题（一道题既有未解决错因、又有已解决且到复查时间的错因）：
  只计“要复习”，不再同时计入“待复查”；封面两徽标之和不再大于
  该科要复习题数。

三处（`dueToday`、`subjectCounts`、首页焦点卡拆分）共用同一个共享
分类函数，不再各自定义。

## 改动文件

- `lib/data/repository.dart`（唯一生产代码改动处，新增共享口径）
  - 新增 `ReviewBucket` 枚举（`pending` / `recheck` / `solved` /
    `none`）与两个静态方法：
    - `reviewBucketOf(List<CauseRecord>)`：按一道题的全部错因记录
      互斥分类——有未解决错因 → `pending`；全部已解决且至少一条
      到复查时间 → `recheck`；全部已解决且无一条到复查时间 →
      `solved`；无记录 → `none`。
    - `isReviewDue(List<CauseRecord>)`：落在 `pending` 或 `recheck`
      即要复习（与旧 `any(status != solved || isRecheckDue)` 等价）。
  - `dueToday`：谓词改为 `isReviewDue(rs)`，行为不变。
  - `subjectCounts`：两个独立 `if` 改为 `switch (reviewBucketOf(rs))`，
    一道题只落一个桶；`rs.isEmpty` 的 `continue` 由 `none` 分支覆盖。
    注释重写：删掉“可同时计入要复习与待复查”，写明互斥拆分与
    `要复习 + 待复查 = homeRevCounts 该科数`；第三项 `solved` 的语义
    在注释里写清——已加入复习、已整理、全部错因已解决且无一条到
    复查时间的题数，即已掌握且不在复查期的题；已掌握但到了复查时间
    的题计入“待复查”而不计入这一项。
- `lib/modules/home/home_page.dart`（焦点卡拆分改走共享函数）
  - `_load` 里的待解决 / 复查拆分由内联 `if (any 未解决) … else …`
    改为 `switch (QuestionRepository.reviewBucketOf(rs))`；
    `solved` / `none` 为防御性分支（`dueToday` 只返回前两类）。
  - 文件头业务口径注释同步更新（删掉“本页用 dueToday + causeRecords
    现算，不改 repository”，改为走仓库共享分类）。
- `test/b5_p1_1_subject_counts_test.dart`（新增回归测试，4 个测试）
  - 共享场景（数学 7 题 + 英语 1 题）：待解决题、纯复查题、混合题
    （待解决 + 已解决且到复查时间）、已解决未到复查题、无记录题、
    未整理题、未加入复习题、英语纯复查题。
  - 断言：`subjectCounts` 数学 `(2, 1, 1)`、英语 `(0, 1, 0)`、
    政治 `(0, 0, 0)`；每科要复习 + 待复查 = `homeRevCounts` 该科数
    （数学 3、英语 1）；`dueToday` 正是那 4 道题。
  - widget 测试：同一场景下首页焦点卡显示“4 道要复习”与
    “待解决 2 道 · 复查 2 道”，与封面三数之和一致。
  - 另有 `reviewBucketOf` / `isReviewDue` 的直接单测（四桶互斥，
    混合错因题只落待解决）。

未动的口径：复习页自身的“要复习”过滤（`review_page.dart` 的
`status != solved || isRecheckDue`）本就是“要不要复习”谓词，与
`isReviewDue` 等价，不属 SR-P1-1 的两处不一致，未改；错题本列表
页的单题错因状态（`_causeStatusOf`，复查优先于已解决）是行内展示
状态，与计数拆分无关，未改。
