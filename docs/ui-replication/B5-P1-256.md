## SR-P1-5 + SR-P1-6：同一根因，修一处归一化函数

根因：编辑器内部约定 `_inners` 的键一律是 `'<页>:<题级框id>'`
（`_innersOf` / `_enterInnerMode` / `_ingestDetected` 全是带页前缀的键），
但两处调用方口径不统一——详情页 `_reworkBoxes` 按裸 `parentBoxId`
分组传 `initialInners`；收集页 `_openBoxEditor` 把 1 层 + 2 层草稿
扁平混进 `initialBoxesByPage`，根本不传 `initialInners`。

修法（只修编辑器入口，两处调用方一字未动）：

- `lib/modules/collect/box_editor.dart` 新增顶层函数
  `normalizeBoxEditorInputs`，在 `_BoxEditorDialogState.initState`
  里一次收敛：
  - `initialInners` 的裸键按父框所在页补成 `'<页>:<父框id>'`
    （父框找不到回退当前页）；已带页前缀的键原样保留；
  - `initialBoxesByPage` 里混进来的 2 层框按 `parentBoxId` 拆出——
    有同页 1 层父框的进 `inners`，无主的进 `standaloneInner`；
  - 同一框 id 在两处出现时只留一份，不凭空多框；
  - 归入 `inners` 的框，`parentBoxId` 与键里的父框 id 对齐。
- 输出侧同款对齐：`_currentDraft()` 返回的 `inners` 框带上与键一致的
  `parentBoxId`（编辑器内新建的默认内框原来没填该字段），入库后
  下次读回仍能按父框归属，不漂移成独立题内框。
- 顺带堵住归一化引入的回归：`initState` 的“本页无草稿才用检测结果”
  与 `_autoDetectIfEmpty` 的“切页空页才检测”，“有框”都按归一化后
  的三处算（1 层、2 层、独立题内框都算）。只看 1 层框会把“只有
  2 层框的页”当成空页，检测结果会把草稿覆盖掉。

效果链（修后）：P1-5——旧内框在题级框内嵌套显示，双击进内框模式
沿用旧框（不再造 stem/option/figure 三个默认框），确认只入库
1 个内框；P1-6——草稿 2 层框归入 `inners['<页>:<父框id>']`，
内框模式下可拖动、可删除，确认时 `_confirmSplit` 的
`boxesByQuestionId[qid] = [box, ...?result.inners['$p:${box.id}']]`
能取到它，不再丢弃；取消时 `onSaveDraft` → `saveDraftBoxes`
按同一口径写回。

## SR-P1-2：保留任务重建收进确认拆题同一事务

修法（首选方案）：`confirmSplitInto` 事务内，在删原任务之后、
同一事务里重建保留任务 + 写回未框页草稿。

- `lib/data/db_collect.dart`：`confirmSplitIntoImpl` 新增可选参数
  `retainedTask` / `retainedBoxesByPage` / `retainedInners` /
  `retainedStandaloneInner`（无未框页时不传，行为与原来完全一致）。
  保留任务与原任务同 id（先删后插）；草稿按页展平写回，未框页
  本就没有 1 层框，所以 `inners` 按键里的页码全量取（不沿用
  `saveDraftBoxesIntoImpl` 那种“只取 boxesByPage 里 1 层父框的
  inners”的取法，否则未框页的 2 层草稿仍会被丢）；同页重复框 id
  去重；`page_rotations` 随保留任务行一起入库。
- 透传：`AppDatabase.confirmSplitInto`（`lib/data/database.dart`）、
  `AppDatabase.confirmSplit`（`lib/data/db_collect.dart`）、
  `QuestionRepository.confirmSplit`（`lib/data/repository.dart`）。
- `lib/modules/collect/collect_page.dart`：`_confirmSplit` 在确认前
  就构造好保留任务与未框页草稿，随 `confirmSplit` 一起传进去；
  删掉确认后事务外的 `saveCollectTask(retained)` +
  `saveDraftBoxes(...)` 两步重建。Batch 3 的 P1-2 行为原样保留：
  确认前弹“还有 N 页没有框”提示未框页数与页码、点取消什么都不拆、
  保留任务回「待框选」从首个未框页继续修。

## 环境说明（clang 缺失与临时垫片）

- 本机 `/usr/lib/llvm-18/bin/clang` 已随 VM 替换消失（`/usr` 外文件

  `pdfium_dart` 的 native-assets 钩子重建时报
  `No compiler configured on host 'linux_x64'`，一度导致任何测试
  都跑不起来（此前能跑是靠暖缓存，多文件调用触发钩子重建后失效）。
-  workaround（仅用于本次测试命令，未改产品代码）：`/tmp/clang-shim/clang`
  是一个 `exec /usr/bin/gcc "$@"` 的垫片，resolver 只校验
  `clang --version` 输出不含 "Apple clang"，gate 小 C 文件用 gcc
  编译通过；本次全部测试均用
  `PATH=/tmp/clang-shim:$PATH LD_LIBRARY_PATH=.../onnxruntime-1.4.1/linux flutter test`
  跑通。`apt-get update` 已跑完一半后停掉（镜像约 88 kB/s，
  装真 clang 1:18.0 需另下约 200MB，未装）；彻底修复应装回真 clang，
  垫片在 `/tmp`，重启即失。
