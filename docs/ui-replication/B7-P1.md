## SR3-1 — `readZip` 重名判重可被路径写法变体绕过（P1）

### 修法

`lib/services/zip_archive.dart`：

- 新增共用归一化函数 `normalizeZipEntryName`（`\`→`/`、折叠连续 `/`、消解 `.` 段；`..` 段保留不消解，以免掩盖穿越）。
- `validateZipEntryName` 改用该函数：绝对路径与盘符在归一化**前**判（归一化会折叠掉开头的空段，`//slices/q1.png` 归一化后不再以 `/` 开头）；`..` 段在归一化后判；归一化结果为空（如 `.`、`///`）按“条目名为空”拒绝。空段（`//`）与 `.` 段本身不再拒绝——归一化后它们与规范写法同一文件，重名时由判重拒绝，单条时落盘由路径解析折叠。
- `readZip` 的 `seenNames` 判重键改为 `normalizeZipEntryName(entry.name).toLowerCase()`（仅用于比较，不改存名与落盘路径），覆盖 `//`、`/.`、反斜杠与 Windows 大小写变体。`backup.json` 重名例外不变（按原始名判断，恢复取最后一个，进位跳过它）。
- staging / 进位路径**未改**用归一化键（任务书是“也可”，非必须）：`readZip` 现已在进 staging 前拒掉一切撞车的变体，staging 不可能再见到同名变体；单条变体（如单独一个 `slices//q1.png`）经 `_resolveInsideDir` 的 `p.normalize` 正常落盘。用例已钉住单条变体可读出、存名原样保留。

### 用例（`test/b5_p2_data_test.dart`，SR2-17 组内新增 2 个）

- `SR3-1：// 与 /. 变体、反斜杠与大小写变体同样判重`：`slices//q1.png`、`slices/./q1.png`、`slices\q1.png`、`Slices/Q1.png` 各与 `slices/q1.png` 配对，均抛 `ZipFormatException`（含“重复条目”）；单条 `slices//q1.png` 可读出、存名不变。
- `SR3-1：// 变体重名备份恢复报“已损坏”，不误报“文件写不进去”`：端到端 `importBackupZipInto`，断言含“已损坏”且不含“文件写不进去”，原库问题数不变。

## SR3-2 — 报告 `_isMastered` 与错题本不同义，陈旧记录下分布数 ≠ 封面数（P1）

### 修法

`lib/modules/report/report_page.dart`：

- `_isMastered` 改用与错题本/首页同一的记录口径：`QuestionRepository.reviewBucketOf(该题现存全部 CauseRecord) == ReviewBucket.solved`，不再按 `allCauses` 逐因查记录。无记录的题仍不是已掌握（`reviewBucketOf([]) == none`）。

- `docs/ui-replication/B6-P2-WRONGBOOK.md` 的 SR2-29 小节修正“与错题本同义”说法：注明原说法不准确（报告版曾逐因查、错题本版只看现存记录，陈旧记录下双向偏离 1 道），现已改用同一记录口径。
- 未动 `_causeGroups` / `_kpGroups` 的按错因查记录逻辑（弱点 Top5 本来就是按错因分组，已解决错因不进组；见遗留第 2 条）。

### 用例（新文件 `test/b7_p1_sr3_2_test.dart`，2 个，实跑验证）

- 同一份 FakeRepo（`_StaleRepo`，只覆盖读方法，不碰真实数据库）同时泵报告页与错题本页，直接对照两边显示的数字——分布行 `数学 · N 道错题` vs 封面“道题”数：
