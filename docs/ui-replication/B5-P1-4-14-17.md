## SR-P1-4：`_importPdf` 末尾写库失败逃出 enqueue（已修）

- 现象：渲染成功后写 `needBox` 状态的 `upsertCollectTask(done)` 在任何 try 之外；写库失败时异常逃出 `enqueue`，任务卡 `importing`、整批中断。
- 修法（两道防线）：
  1. `_importPdf` 末尾的 upsert 包进 try/catch：失败走 `_failAndClean`（失败任务 + 清目录）；其自身写库再失败时返回内存里的 failed 任务，绝不抛到 `enqueue` 外。
  2. `enqueue` 内 `_importPdf` 调用点后的收尾 upsert 也加 try/catch：重写失败也不中断整批，`_importPdf` 返回的任务状态即为准（内存里），继续下一个文件。
- 失败文案：`导入失败：这个 PDF 渲完了，但写不进任务列表（…）`。

## SR-P1-14：图片 20MB 上限只提示不执行（已修）

- 现象：`maxImageBytes` 只被 `oversizeHint` 用到；PDF 超 50MB 进 failed，图片超 20MB 照常入库；横幅标题“只是提示，不直接判失败”与 PDF 硬失败自相矛盾。
- 修法（方案 a：图片也硬判，与 PDF 一致）：
  1. `enqueue` 里把 PDF 50MB 检查扩成统一的单文件尺寸硬判：PDF 50MB / 图片 20MB，复制前先判，超了直接进 failed 任务、不复制不渲染。PDF 失败文案一字未动（`超过 50MB 上限，请拆成多个小 PDF 再导入`）；图片文案：`这张图片有 XMB，超过 20MB 上限，请压缩到 20MB 以内再导入`。
  2. `oversizeHint` 文案同步改硬判口径：`文件较大（25.0MB），超过 20MB 上限，导入会失败。`（删掉“超过建议上限…仍可继续导入”）。
  3. 收集页超限横幅统一文案：标题改为`文件超过大小上限，导入会失败。`；正文改为“……可以先压缩再重新选；如果仍要导入，超限的文件会记为失败任务，其他文件正常导入。”；`_pickFiles` 处注释同步更新（重复只是警告，超限导入时记失败任务）。
  4. 超限横幅的“仍然再导一份”按钮文案保留（仍是“继续导入”的意思），由正文说明后果。

## SR-P1-17：`enqueue` 的重复判断是空分支（已修）

- 现象：`duplicate` 算出来没有任何行为；同批两次选同一文件建两个任务。
- 修法：去重收进 `enqueue`，按源文件路径去重——`seenPaths` 集合边建边更新，同批重复文件只建一个任务，后面的直接跳过（跳过发生在建任务行之前，不写库、不建目录）。删掉已死的 `existing` 快照 + `duplicate` 空分支（`duplicate` 变量按报告要求删除，不留空分支）。
- 口径说明（有意保留）：**跨批重复不在这里拦**。D-08 定了重复导入允许重导——收集页先弹“已经导入过”提示，用户点“仍然再导一份”才进 `enqueue`；若服务层拦掉跨批重复，该按钮会静默失效。回归测试把这一口径锁死（两次调用各建一个任务）。
