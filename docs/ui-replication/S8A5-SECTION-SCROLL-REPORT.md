# S8A5：点段头后页面上滚——根因是内容区垂直居中，已修

## 1. 定性：缺陷，不是故意的

点段头后页面内容整体上窜，是**缺陷**，已修。判定依据：

- **没有设计意图**：HTML 原型里段头点击处理全是纯切换 + 重渲染，不滚
  动（`index.html:4283` 整理、`4550` 设置、`4553` 学科管理）。
  唯一一处 `scrollIntoView` 是整理台“待补充”跳字段链接（`4277` 行），
  且明确写了“滚动发生在定高工作台盒子内部，页面外部不动”，聚焦还特意
  用了 `focus({ preventScroll:true })`。HTML `.main` 是常规顶对齐块，
  内容从不垂直居中。
- **滚动量不稳定**：上窜量 = 被切换段体的高度变化的一半，随段而异
  （实测 119px、30px 两种；见 §3），不是固定设计值。
- **影响阅读连续性**：点的段头本身会从光标下窜走约 119px，用户要点
  下一段得重新找位置；标题、导航之上的内容也跟着动。

R11 §8.3 的括号备注“焦点滚动，R1 共享组件既有行为”是**错的**，
见 §4。

## 2. 根因

`lib/app.dart` 内容区 `Row`（`Positioned.fill` 内）没有写
`crossAxisAlignment`，取默认值 `center`；内容区 `Container`
（`Expanded`，主轴拉满、交叉轴随内容收起）按**页面内容高度**
收起并**垂直居中**。内容短的页就悬在窗口中间，上下露出背景色带。

点段头展开/折叠改变内容高度 → 容器重新居中 → 整个页面上下跳，
跳动量 = 内容高度变化的一半：

| 状态（设置页，深色，1280×720） | 内容区 surface 带（x=1250 实测） | 内容高 | 容器顶 | 标题字行 |
| --- | --- | --- | --- | --- |
| 全折 | 149–570 | 421px | 149 | 181–203 |
| 点「外观」展开 | 30–689 | 659px | 30 | 62–84 |
| 再点「复习」（外观收起） | 0–719（满高） | >720px | 0 | 32–54 |

- 展开外观：内容 +238px（外观段体高），容器顶 149→30，标题上窜 **119px**。
- 再点复习：外观收起（−238px）+ 复习展开（约 +500px），内容超视口，
  容器顶被钳制到 0，标题只再上窜 **30px**（62→32）。
- 全折时标题离顶 181px，纯属容器居中，与滚动无关；滚轮回顶 6 次、
  静置 1 秒复截，位置纹丝不动（`33/34` 对照截图），不是过渡态。

R11 说的“约 136–158px”：窜动量 = 段体高度变化的一半，段体
272–316px 高即落在这个区间（如更大的段体）。R11 没记具体页面，
本次无法把该数字对到某一段，但机制覆盖整个区间；实测外观段
119px、第二次切换（钳制态）30px，见 §3 表。

机制上容器满高时居中无位移，修后复测（§5）位移为 0，结论一致。

### 3.4 滚动偏移本身：点按前后恒为 0

短视口（1280×400）widget 探测：全部段头点按场景下滚动偏移
`offset` 恒为 0.0，段头屏上位置只随内容伸缩移动（如点「复习」
时「复习」段头上移 229px = 上方「外观」段体高，offset 不动）。
唯一能让 offset 变化的是**被动钳制**：已滚到底时收起上方段体，
内容缩短、offset 被钳制回落（如 494.3→364.0），这是 Flutter
标准行为（HTML 同样会钳制），与本次缺陷无关。

## 4. 排除“焦点滚动”

R11 的“焦点滚动”归因不成立，三条证据：

1. **点按不请求焦点**：widget 探测里点段头后
   `FocusManager.instance.primaryFocus` 始终是 `_ModalScopeState`
   的 Focus Scope，未落到段头。`Focus` 组件本身不处理点按聚焦；
   `_QmPressable`（`uikit.dart:134` 起）的 `GestureDetector` 只调
   `onTap`，不调 `requestFocus`。
2. **无滚动调用**：全仓 grep `ensureVisible` 只有整理台两处
   （`organize_page.dart:1021`“待补充”跳字段、`1963` 队列定位），
   都不在段头点按路径上；`_toggleGroup`/`_toggleSection`/详情
   `_buildSection` 全是纯 `setState` 翻转展开态。
3. **框架层面**：Flutter 的 `Scrollable` 不在焦点变化时自动滚动；
   只有键盘 Tab 遍历的 `defaultTraversalRequestFocusCallback`
   才会 `ensureVisible`，鼠标点按不走这条路。
   （`focus_traversal.dart:204` 附近，`alignment: 1`，仅遍历用。）

任务里给的三处代码线索（`organize_page.dart` 约 1954/1963/1021 行、
详情页 `_titleFocus` 等约 196–202 行）也已核对：1954/1963 是队列
定位 `_scrollToCurrent`，1021 是“待补充”跳字段，详情页
`requestFocus` 只在进编辑模式聚焦字段时触发——均与段头点按无关。

## 5. 修法与修后验证

### 5.1 修法（最小改动，一处）

`lib/app.dart` 内容区 `Row` 加一行：

```dart
crossAxisAlignment: CrossAxisAlignment.stretch,
```

并附注释说明原因（A5、119px、不是焦点滚动）。容器恒满高、顶对齐，
与 HTML `.main` 一致。`start` 不行：容器仍会收起，短页面下方会露
背景色带；`stretch` 让 surface 铺满整个内容区。

副作用（均向 HTML 靠拢，非回归）：

- 短页面（设置/学科管理全折）标题由离顶 181px 回到 32px（26px
  内边距 + 字高），与 HTML 顶对齐一致；首页标题由 71px 回到 35px，
  其余内容不变（`45-home-fixed.png`）。
- 左导航此前也被居中（底部约 15px 露背景色带，`30` 图 x=50 y=710
  处为背景色）；`stretch` 后导航拉满到底（同位置变为 surface2），
  与 HTML 满高导航一致。导航各行位置随之上移约 21px（首页 102→85
  等），属同一修复的直接结果。

## 6. 方法说明与过程记录

- 像素测量：标题/段头取 x=245–295 列亮像素（>150）行段；
  surface 带取 x=1250 列 `#262B33` 行段；关键帧用模板匹配
  （64×N 灰度带，dy ∈ [−320, 320] 搜最小平均绝对差）复核，
  详情/整理两处匹配误差均为 0.00。
- 走过的弯路（已排除，不影响结论）：初版模板匹配用的带子落在
  纯色背景上导致歧义匹配（误差 7–10），后改用亮像素行扫描定位；
  一次点击坐标落在段头间隙（y=128，段头盒底约 125）未命中，
  复截对照组才发现；另有一次导航点击坐标用的修前旧 y 值，
  修后导航上移约 21px 导致未命中，改按修后截图重定坐标后成功。
- 整理台两处 `ensureVisible` 与详情页编辑聚焦均与段头点按无关
  （§4），本次未动；队列定位、跳题、待补充跳转行为不受影响。
