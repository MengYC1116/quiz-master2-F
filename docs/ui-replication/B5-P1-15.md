# B5-P1-15：CompactSliceThumb 的 Image.file 补 errorBuilder

- 问题：SR-P1-15（见 `SELF-REVIEW.md`）。`CompactSliceThumb`（`lib/widgets/widgets.dart`）的 `Image.file` 没有 `errorBuilder`；切片文件存在但内容损坏/解码失败时，紧凑列表只剩空白框，`failed`/`missingRealImage` 两条占位分支都走不到（`existsSync` 为真），与大卡片（`QuestionSlice` 走 `_missingImagePlaceholder`）行为不一致。
- 结果：已修复并验证通过。

## 改动文件

1. `lib/widgets/widgets.dart`（`CompactSliceThumb.build`，约 :573–622）
   - 把 `failed`/`missingRealImage` 分支原有的内联失败占位抽成局部变量 `failedPlaceholder`（学科图标 14px + “加载失败”/“图片缺失”文案，样式/尺寸不动），该分支与新增的 `errorBuilder` 共用，不另造样式。
   - `Image.file(sliceFile, fit: BoxFit.cover, cacheWidth: 128)` 补 `errorBuilder: (context, error, stackTrace) => failedPlaceholder`，并加 `// SR-P1-15` 注释。
   - 口径说明：紧凑缩略图容器只有 64×48，复用的是其已有紧凑占位（与 `QuestionSlice._missingImagePlaceholder` 同款口径的紧凑尺寸版——学科图标 + “图片缺失”/“加载失败”文案）；完整版占位（34px 图标 + “学科 · 题型” + “图片缺失，可重新导入/重新框选”）放不进 64×48，故未直接复用 `_missingImagePlaceholder` 本体。解码失败时文案为“加载失败”（文件存在、`failed=false`、`missingRealImage=false` 时三元式取该分支），与原 `failed` 分支一致。
   - 未动 `box_editor.dart:1352` 的页图 `Image.file`（自审称“顺带补即可”，有 `_pageImageFailed` 门控、风险低；本任务修法只定 `CompactSliceThumb`，留作可选后续，见遗留问题）。

2. `test/b3_p11_layer2_downgrade_test.dart`（已有 errorBuilder 回归文件，新增 `CompactSliceThumb errorBuilder` 组 + `_pumpThumbWithDecode` helper）
   - `损坏的切片文件：解码失败显示“加载失败”占位`：`slices/bad.png`（现写非 PNG 内容）→ 显示“加载失败”+ 学科图标“数”，`tester.takeException()` 为空。注意：`errorBuilder` 是在 `Image` 内部渲染占位，`Image` widget 本身仍在树上，故不断言 `find.byType(Image)` 为空（初版断言写错，测试已据此修正并在注释中说明）。
   - `有效切片：正常显示图片，不显示失败占位（对照）`：`slices/good.png` → 显示 `Image`，无“加载失败”，无异常。
   - 解码推进沿用本文件既有做法：挂载用普通 `pump` 在 `runAsync` 外，`runAsync` 内反复 `pump` + 真实延时推进（`pumpAndSettle` 会挂住）；夹具与 `QuestionSlice` 组同款（临时目录 + `testDataDirectory`，测试用临时库，不碰真实演示库）。
