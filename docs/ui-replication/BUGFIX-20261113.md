# Win11 实机验收 Bug 修复（2026-11-13）

Meng 在 Win11 上跑 `ui-replication` 分支（head `b301135`）发现两个小 bug。
本报告记录原因、修法与 Linux 真机验证。两处改动都不碰 Schema、不改业务
规则、不增删功能。

## Bug 1：学科管理 → 错题本封面样式，点某科封面后该科跑到最下面

现象（Meng 截图图 1–4）：点第一行数学的某封面，数学掉到最下面；再点
第二行的封面，第二行又掉到最后一行。已在 Linux 真机复现并确认。

根因：`lib/data/database.dart` 的 `upsertSubject` 用
`ConflictAlgorithm.replace`。SQLite 的 REPLACE 是先删后插，被改的那行
rowid 变成最大；`allSubjects()` 又没有 `ORDER BY`，读出来就是 rowid
顺序——点谁谁掉到底。改名、改封面、改颜色走的都是同一条 upsert，所以
都会触发。

修法（只改 `lib/data/database.dart`）：

- `upsertSubject` 改为先 `UPDATE … WHERE id = ?`，影响 0 行时才
  `INSERT`（原地更新，rowid 不动，顺序不动）。
- `allSubjects()` 加 `orderBy: 'rowid'`，把“按插入顺序”写死（subjects
  表没有 `sort_order` 列）。

同类隐患（本次没动，待 Meng 定）：`tags` / `exams` /
`knowledge_points` 的读方法同样没有 `ORDER BY`，且 upsert 同样用
REPLACE；改标签/试卷名时顺序也会漂。想修的话说一声。

## Bug 2：点左侧某模块后，鼠标悬停其上变纯黑

现象（Meng 截图图 5）：点“复习”后鼠标停在上面，选中项变纯黑 pill。
Linux 的 R11 回归截图里其实早有同样现象（`shots/r11/regress-light/`
各页选中项均为纯黑），当时没做像素检查，漏了。

定位过程（关键发现）：

- 不是单纯悬停：只悬停不点，pill 保持蓝色；只有“导航点过去、鼠标还
  停在上面”时才变黑。点已选中的项、或鼠标移开再移回，都不变黑。
- 颜色跟着 `hoverColor` 的 RGB 走：旧代码 `hoverColor` 留空（主题默认
  黑 4%）→ 纯黑；改成白 10% → 纯白；改成透明 → 还是纯黑（透明的 RGB
  是 0,0,0）。即真机渲染里 InkWell 遮罩的 alpha 被忽略，按 RGB 不透明
  画出；且导航重建时会重建悬停遮罩，用当前 `hoverColor` 重画。
- HTML 原型本身：选中项的 `aria-current` 规则优先于 `:hover`，悬停时
  选中项底色就是 accent 不变。

修法（只改 `lib/widgets/app_shell.dart` 的 `_NavItem` /
`_CollapsedNavItem`）：选中态四层反馈色（hover / splash / highlight /
focus）全部取 `palette.accent` 本身。无论 alpha 通路是否生效，画出来
都是蓝色；未选中项保持 `surface` 悬停不变。深色同理（accent `#7FA8D0`）。
