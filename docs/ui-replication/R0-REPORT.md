## 5. 不可动的业务口径（R1 换皮时只能换皮、不能改语义）

1. 首页“要复习的数量”与导航速览同一口径（`repository.dart:59–85` `dueToday()` / `homeRevCounts()`）：手动加入复习（`review_joined=1`）且已整理（`is_organized=1`）且至少一个错因未解决或已到复查时间；**数题不数错因**。
2. 每科三数（要复习 / 待复查 / 已解决，`repository.dart:87–117`）：不显示总题数；一道题可同时计入要复习与待复查；“已解决”要求该题全部错因 solved 且无复查到期项；同样限定 `reviewJoined + isOrganized`。
3. 错因复习模型默认值（`models.dart:393–413`）：复查间隔 7 天（3/7/14）、治愈自查 2 次（1/2/3）、每会话错因数 0 = 不限（5/10/不限）、跳过上限 2 次（1/2）；`recordSelfCheck`（`repository.dart:124–168`）：`unsure` 不算；`unsolved` 则 `solvedCount` 清零、回 `inProgress`、复查日作废；`solved` 满次数才变 `solved` 并设 `recheckDate = 今天 + 间隔天数`。
4. 错因状态机只有 `pending / inProgress / solved` 三态；`cause_records` 表 `UNIQUE(question_id, cause)`；无错因的题加不进复习；取消加入后记录保留、再加入续接。
5. 错题本收录口径：非归档列表只收 `isOrganized` 的题；默认不显示已掌握；默认排序时间新→旧、默认每页 10（10/20/30/40/50）；`is_demo=1` 是“清空演示数据”唯一判定条件。
6. 多值字段逗号拼接存 TEXT（`folder_ids / knowledge_ids / error_types / custom_error_types / tags`；`review_state.queue` 为 `"questionId|cause"` 逗号拼接）——UI Kit 的标签 / 多选组件不得改分隔符或引入含逗号的值。
7. 固定枚举与预设：错因 `审题失误/概念不清/计算错误/方法不会/其他`；学科顺序固定数学/英语/政治；每科预置文件夹 `试卷/平时作业/模拟卷`，同科不可重名，子文件夹只一层，`sort_order` 步进 10；封面 6 样式 + 7 预设色，不可扩展取色器。
8. 其他默认值：主题默认跟随系统、字号标准、问候语默认“今天也要加油呀”、错题本默认大卡片视图、复习列表默认按加入时间排、重做答案默认隐藏、导入上限 PDF 50MB / 图片 20MB 且超限只提示不硬拦。

## 6. 已发现的出入与待裁决项（R0 记录，不动手）

### A. 代码与 HTML 的视觉 token 偏差（R1 重点）

1. **深色纸面（最大分歧，需负责人裁决）**：代码 `darkPaper = 0xFF262B33` 冷灰；HTML 深色 `--paper:#D8DCE2` 是浅灰纸。R1 以哪边为准，须先裁决，不可静默沿用代码值。
2. **深色主色**：代码 `darkAccent = 0xFF8AB6FF` 偏亮偏蓝；HTML `--accent:#7FA8D0` 冷雾蓝；且代码深色 `FilledButton` 仍用浅色 accent，与导航选中块（`0xFF7FA8D0`，与 HTML 一致）不是同一个蓝。
3. **主色 1 位差**：代码 `accent = 0xFF2F7CF6` vs HTML `--accent:#2E7CF6`；学科色英语代码 `0xFF1F9D66` vs HTML `--eng:#00A884`、政治 `0xFFE0524D` vs `--pol:#EF4444`；深色学科冷雾色三处与 HTML 一致。

### A2. 设计说明 vs 真实业务说明（细化分类）

**纯设计说明（不抄入应用）：** 原型 artifact 头（QUIZ-MASTER2 · 交互原型、平台/风格/演示数据声明）、顶部「正常态 / 空状态 / 错误态」切换器与「当前页 / 状态」标签、主题切换行；各页 `.psub` 副标题里的大段规则文（如目录页整段树规则说明、学科管理“管架子……”整段、设置“不做”清单、复习“按错因排，不按题排”全段、报告“只回答三个问题”全段、收集任务下方“任务保留口径”整段、整理台“平时只看左边的题图和右边的表单”）；折叠区副标题里的口径句（如修框切片“每个框存一张图，只存图不做 OCR”、错误类型区“报告仍按固定枚举归因”）；全部 JS/CSS 注释；`viewStub` 占位描述；原型内带“原型里……”的演示性提示句。
**真实业务说明（保留，含措辞）：** 全部按钮/占位/下拉文案；全部确认框文案（删了就没了，确定吗？／删学科长文案／删文件夹带数文案／恢复覆盖题库／清空演示数据／清理缓存）；全部空状态标题 + 说明 + CTA；全部错误横幅（按场景的具体原因）；业务规则提示句（每次导入都自己选、不默认；一道题可进多个文件夹，题只存一份；自定义类型只跟这道题；答案和解析默认藏起来；选「不确定」不算；改完位置要重启软件才生效；上次是这么补的……）；小伙伴气泡语（我陪你慢慢来／今天休息一下／上次到这里／这一轮辛苦啦）。
**例外：** 详情副标题“选错自己承担”是原型口吻，**不要原样抄进真实应用**（改为中性表述，如“导入时选定，详情与整理台均不可改”）；焦点卡“点这张卡片去复习页”这类自指说明也不要抄。

### A3. 原型自相矛盾 / 缺失 / 死代码（R1 前需负责人定夺的在前）

1. **学科管理存在死按钮处理器（需定夺）**：`bind()` 里有换学科图标、隐藏学科、学科上下移的完整处理逻辑与 toast，但 `viewSubjects` 渲染的学科行只有「改名」「删除」两个按钮——图标更换、隐藏学科、学科排序在原型里点不到；同时 `HIDDEN_SUBS` 逻辑与错题本筛选面板提示“（有学科已在学科管理中隐藏……”却假定隐藏功能存在。按已定决策（学科管理只有增/删/改名），隐藏/排序/换图标很可能是不应做的——**Flutter 对照前需负责人定夺：实现还是删除**，不要默认照抄处理器。
2. **错题本学科筛选处理器是死的**：`bind()` 有 `nb-f-subject` 的 change 处理，但列表筛选面板根本没渲染这个下拉；`nbFiltered()` 里仍有过滤分支。无害，Flutter 不要为此加学科下拉。
3. **整理台注释与 H 方案自相矛盾（注释过期）**：两处注释仍写固定高度工作台盒内滚动；H 方案注释与 CSS 明确写整页滚动，代码实际用 `scrollIntoView`（页面滚动）。以 H 为准，Flutter 按整页滚动实现。
4. **固定高度内滚容器是“例外”不是“通则”**：收集任务 >3 个时变 `.task-scroll`；错题本大卡片 >2 张时变 `.nb-paper-cards`（约 2.5 张卡，第三张露一半）。复习列表与整理台是整页滚动。Flutter 必须按页区分，不能统一成一种滚动。
5. **学科管理文件夹残留代码**：`FOLD_SUBJ / FOLD_OPEN / FOLD_SEL_MODE / FOLD_CHECKED / SETF_DRAG` 等变量与整套 `.set-fold-*` CSS 仍在文件里，但 `viewSubjects` 只渲染 4 组，无文件夹组。不要把这套残留实现成学科管理里的第五组。
6. **旧翻卡模型残留**：`REV = { flipped, streak, status … }` 与 `syncRevStatus` 仍在代码里，`viewStub` 里的错题本/复习占位描述还是旧口径（列表行含「下次复习时间」）。`viewStub` 对 9 个正式页永不渲染，`REV` 与新 `REV2`（四步会话）并存——Flutter **只按 REV2/cause 模型实现，不要复活翻卡与「下次复习时间」字段**。
7. **首页「待整理 3」是写死的演示数**：`homeCBottomHTML` 里三科待整理都是字面量 `3`，左导航「学科速览」里的“待整理 3”也是写死在 HTML 里的；只有「待复习」是算出来的。真实应用三处待整理都必须按待整理队列实时算。
8. **报告两类数字的分母口径不同**：已解决错因按「解决日期在范围内」算，待解决错因与薄弱点按「题目收集日期在范围内」算；复查通过率按历史记录里 `note` 以「复查」开头的字符串匹配统计。Flutter 实现时极易按同一分母算错，需单独写单测。
9. **缺失/未覆盖的状态**：书架 >6 本时的分页器有实现但演示只有 3 本，未验证；整理台「批量确认整理」时有题没选文件夹被拦下的形态只有 toast 一句话，未给出被拦题的定位方式；收集「导入中」取消后任务直接删掉，无二次确认（与删除题目二次确认不一致，是有意还是遗漏需确认）；复习列表「已解决但未到复查时间」的分组可点开看记录，但点开后能否直接开始复查/重新加入没有入口；详情页「取消编辑时若有改动提示保存」的确认框只有处理，具体文案未完整呈现。
10. **一处文案与行为不完全一致**：错题本列表搜索框占位写“按文件夹 / 标签 / 学科 / 试卷 / 日期查找”，但实现里搜索 haystack 还包含知识点与错误类型。Flutter 以实现为准（元数据全查、题干不查），占位文案建议按实现补全。
