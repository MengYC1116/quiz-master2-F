## 1. 5 分钟上手

### 项目是什么

quiz-master2 是一个 **Windows 个人智能错题本**，只给一个学生自己用。
核心是错题管理：收集题目 → 整理归类 → 按错因复习 → 掌握。
一句话流程：**收集 → 整理 → 复习 → 掌握**。

技术栈：**Flutter + SQLite**。Flutter 是 Google 的跨平台界面框架，
用 Dart 语言写；SQLite 是存在本地文件里的轻量数据库，不用装数据库服务器。

锁定版本（不要升级）：**Flutter 3.47.9 / Dart 3.13.7**，
见 `pubspec.yaml`：

```yaml
version: 0.1.0+1
environment:
  sdk: ">=3.13.0 <4.0.0"
  flutter: ">=3.47.0"
```

依赖只有三个（`pubspec.yaml` 的 `dependencies`）：

```yaml
dependencies:
  flutter:
    sdk: flutter
  sqflite_common_ffi: ^2.3.6   # SQLite，桌面端用的版本
  path: ^1.9.1                 # 拼文件路径
  file_picker: ^8.0.0          # 系统文件选择框
```

### 怎么跑起来（在 Win11 上）

```powershell
cd D:\quiz-master2-F
flutter pub get
flutter analyze
flutter run -d windows
```

打包成安装用的 exe：

```powershell
flutter build windows --release
```

产物在 `build\windows\x64\runner\Release\`。最后打包成安装程序才需要
Inno Setup，平时跑和测都不需要。

### 改完怎么验证

改完代码后，依次做三件事，全部通过才算改好：

1. `flutter analyze` —— 输出 `No issues found`（静态检查，语法和类型错误都会报出来）。
2. `flutter test` —— 全部测试通过（`test/` 目录下是测试文件）。
3. 眼睛看一遍：跑起来，点一点改动涉及的页面，确认显示和操作都对。

在 Linux 验证机上跑界面要用虚拟屏幕（Xvfb），但你的主力验证就是自己的 Win11 真机：
字体、窗口大小、DPI 显示都以 Win11 真机为准。

## 3. 数据流

### 一张图

```
SQLite 数据库文件（quiz-master2.db）
        ↓  读 / 写
AppDatabase（lib/data/database.dart，单例，全应用只有一个实例）
        ↓  查业务口径（要复习的题、自查一次错因……）
QuestionRepository（lib/data/repository.dart）
        ↓  页面调用
9 个页面（lib/modules/...）
        ↓  用户点按钮
调 Repository 的方法 → 写数据库 → 页面重新读库刷新显示
```

关键点：**页面不直接碰数据库，也不直接互相传数据**。页面只认识
`QuestionRepository`（在 `app.dart` 里创建好传给各页），只靠题目 ID
和学科 ID 跳转。一道题在数据层只存一份，可以挂多个文件夹、多个标签。

### 数据库在哪

- Win11：`%LOCALAPPDATA%\quiz-master2\quiz-master2.db`
  （一般是 `C:\Users\你的用户名\AppData\Local\quiz-master2\quiz-master2.db`）。
- Linux 验证机：`~/.local/share/quiz-master2/quiz-master2.db`。

数据库位置可以在设置页改：改完后新路径写进默认数据目录下的
`db_location.txt` 标记文件（`setCustomDataDirectory`），下次启动时读标记文件。
因为设置本身存在数据库里，换库后读不到旧设置，所以位置必须存在库外面。

### 核心模型（`lib/models/models.dart`，逐个讲）

**Subject（学科）**：`id`（`math` / `english` / `politics`）、`name`、
`color`（学科色）、`icon`（单字图标，如“数”）、`coverStyle`（封面样式）、
`coverColor`（封面颜色）。初始三科写死在 `Subject.all` 里（顺序固定数学/英语/政治），
`Subject.byId(id)` 按 id 取，找不到时回落到数学。
注意：学科色和封面色是两套独立的取值（封面蓝 `#2F7CF6` 和学科蓝 `#2E7CF6`
不是同一个值，不要合并）。

**Question（一道题）**：最小单位，整题保存，永不拆分。主要字段：
`id`、`title`（题名）、`subjectId`、`folderIds`（可多个）、`examId`、
`knowledgePointIds`（可多个）、`errorTypes`（固定枚举多选）、
`customErrorTypes`（自定义错因）、`tags`、`answer`、`explanation`、
`notes`、`reviewCount`（复习次数）、`isOrganized`（是否已确认整理）、
`isDemo`（演示题标记，“清空演示数据”只删这类题）、`isFavorite`、
`isArchived`、`reviewJoined`（是否手动加入复习）、`createdAt`。
`allCauses` 是个方便写法，把固定错因和自定义错因拼成一个列表：

```dart
/// 全部错因（固定枚举 + 自定义）。
List<String> get allCauses => [...errorTypes, ...customErrorTypes];
```

**CauseRecord（错因解决记录）**：复习是按错因治的，一道题的每个错因各一条记录。
字段：`questionId`、`cause`、`subjectId`、`status`、`solvedCount`
（同一错因在同一道题上自查“已解决”的累计次数）、`lastCheck`（上次自查时间）、
`recheckDate`（复查日）、`remedyHistory`（每次写补救的内容，带日期，新→旧）、
`joinedAt`（加入复习的时间，复习列表按它排序）。

**CauseStatus（错因状态，三态）**：枚举只有三个值：

```dart
enum CauseStatus { pending, inProgress, solved }
```

`pending` 待解决、`inProgress` 解决中、`solved` 已解决。中文名在
`CauseStatusLabel` 扩展里（`label`）。

**ReviewSessionState（复习会话断点）**：只有一行（id=1），存 `queue`
（队列项是 `"题目id|错因"` 字符串，按解决顺序排）、`position`（断在哪）、
`updatedAt`。复习中途暂停时存下断点，下次进复习页从断的那个错因继续。

**CollectTask（收集任务）**：`id`、`name`（任务名 = 文件名 + 页 + 题号，不可改名）、
`fileName`、`subjectId`、`status`、`progress`（0–100 百分比）、
`pageCount`、`page`、`error`、`questionId`（修框确认后产出的题目 id）。
状态 `CollectStatus` 有 7 种：`queued` 排队中、`importing` 导入中、
`needBox` 待框选、`boxing` 修框中、`pendingOrganize` 待整理、
`failed` 导入失败、`done` 已整理。

**QuestionBox（框）**：两层框。`layer` 1 = 整题框，`layer` 2 = 题干 / 选项 /
配图辅助区（`type` 是 `question` / `stem` / `option` / `figure`）。
`x, y, w, h` 是相对页面的 0..1 坐标（0.06 表示页面宽度的 6%），框不能超出页面。

**Folder（文件夹）**：按学科分，每科一套，预置“试卷 / 平时作业 / 模拟卷”。
`parentId` 为空是顶层文件夹，不为空是子文件夹，只允许一层子文件夹。
同一科不能有两个同名文件夹。

**Exam（试卷）**：独立实体，一张试卷 → 多道题。字段只有 `id`、`name`、`date`。

**KnowledgePoint（知识点）**：预置树“学科 → 章节 → 知识点”，大学层级
（高等数学、大学英语、大学思政）。`subjectId`、`chapter`、`name`。

**ErrorTypes（错误类型）**：固定枚举 5 个：审题失误、概念不清、计算错误、
方法不会、其他。多选；自定义错因只跟本题，下次可选，不进全局枚举。

**AppSettings（设置）**：全部设置项都在这里，存在 `settings` 表里
（key/value 字符串）。默认值在 `AppSettings.defaults`：

```dart
class AppSettings {
```

### 错因状态机（复习的核心，一定要懂）

旧的翻卡 + 1/3/7/14 天间隔复习已经废弃了。现在的模型是**治错因**：
复习按错因治，不按题目背；一道题有多个错因就治多次。

```
待解决 pending
   │ 自查 1 次“已解决”（还没满 2 次）
   ▼
解决中 inProgress
   │ 再自查 1 次“已解决”（累计满 2 次，默认 cureChecks = 2）
   ▼
已解决 solved ──满复查间隔（默认 7 天）──▶ 自动回来复查
   │ 复查自查“已解决”              │ 复查自查“未解决”
   ▼                                ▼
已解决（新的复查日）            解决中（solvedCount 清 0，重头治）
```

规则细节（都在 `repository.dart` 的 `recordSelfCheck` 里）：

```dart
/// 自查一个错因：result 是 'solved' / 'unsolved' / 'unsure'。
/// - 已解决：solvedCount + 1；满 cureChecks 次 → 已解决，复查日 =
///   今天 + recheckIntervalDays 天；不满 → 解决中（复查日清掉）。
/// - 未解决：solvedCount 清 0 → 解决中，复查日清掉（复查不过，
///   回到解决中重新治，旧复查日作废）。
/// - 不确定：不算，不改记录。
```

自查有三个选项：已解决 / 未解决 / 不确定。“不确定”不计数，下次重做。
一道题所有错因都已解决 = 这道题已掌握。光答案做对了、错因还在，不算掌握。

关键口径（首页、导航、复习列表都用同一套，别自己另算）：

- **要复习的题**（`repository.dart` 的 `dueToday()`）：手动加入复习、
  已整理、至少一个错因还没解决（待解决/解决中）或到了复查时间。
  **数题不数错因**——一道题有 3 个错因也只算 1 道。
- **首页焦点卡与导航速览**用同一个口径（`homeRevCounts()`），所以两处数字一定一致。
- **加入复习是手动的**：题目详情页复习记录区有“加入复习”按钮
  （`repo.setReviewJoined(q, true)`），没有错因的题加不进去；
  点“取消加入复习”后记录保留，再加入可续接。

复习会话的四步（`review_page.dart` 的 `_Phase` 枚举）：
`recall` 看错因 → `remedy` 写补救 → `redo` 重做 → `check` 自查。
补救没有固定模板，用户自己写，保存进 `remedyHistory`，下次复习还能看到
（`repository.dart` 的 `saveRemedy`）。
跳过规则：第一次跳过，该错因排到队尾；第二次跳过，留到下次
（`skipLimit` 默认 2，见 `_skipCurrent`）。
中途暂停会把队列和位置存进 `review_state` 表，下次从断点继续。

## 4. 九页地图

每页一段：文件、路由、打开时读什么、主要按钮点下去发生什么。
页面里的 `widget.repo` 就是 `QuestionRepository`，`widget.onGoXxx`
是 `app.dart` 传进来的跳转回调——页面自己不决定去哪，只调回调，
真正的跳转逻辑在 `app.dart` 的 `_go` / `_goReview` / `_goWrongbookFiltered`。

### 首页 `/home` —— `lib/modules/home/home_page.dart`

职责：问候 + 焦点大卡片（要复习的数量）+ 继续上次 + 快速收集 + 各学科概览。
学科顺序固定数学 / 英语 / 政治。

打开时读（`_HomePageState._load`，一次并行读 5 样）：

```dart
final results = await Future.wait([
  widget.repo.homeRevCounts(),          // 每科要复习的题数
  widget.repo.pendingOrganizeBySubject(),// 每科待整理的题数
  widget.repo.recentTask(),              // 最近任务（继续上次）
  widget.repo.dueToday(),                // 要复习的题列表
  widget.repo.causeRecords(),            // 全部错因记录（拆待解决/复查）
]);
```

主要操作：

- 点焦点大卡片 → 去复习页（`onGoReview`）。
- 点卡片里的“继续上次” → 按最近任务的 kind 跳转：
  整理 → 整理工作台，收集 → 收集中心，其他 → 复习页（`_resumeRecent`）。
  注意 kind 有两套写法（种子写中文“整理”，代码写英文 `organize`），
  本页用 `_normalizedKind` 两边都认，不改数据层。
- 下方每科一格：“要复习 N 道 · 待整理 M 道”，点“错题本”进该科错题本，
  点“去复习”进该科复习。
- 问候语取设置里的 `greeting`，默认“今天也要加油呀”，在设置页改。
- 没有要复习的题时卡片变中性样式，文案“今天没有要复习的，明天再来吧”。

## 5. Dart 速成

只讲这个项目里实际用到的语法。每个语法点都配项目里的真实代码，
注明出处。Dart 和 Java / C# / JavaScript 像的地方很多，重点看不一样的地方。

### 变量与类型

类型写在变量名前。`final` 表示赋值一次后不能再改（类似常量，但值可以在运行时算出来）；
`const` 表示编译时就定死的常量；不写 `final`/`const` 的就是普通变量。

```dart
// lib/models/models.dart
final String id;
final String name;
final int solvedCount; // 整数
final DateTime? lastCheck; // DateTime 是日期时间类型，? 见“空安全”一节
```

`var` 是让 Dart 自己推断类型，少用在公开字段上，局部变量里常见：

```dart
// lib/data/repository.dart
var toReview = 0;
var toRecheck = 0;
```

### class 与 copyWith

Dart 里没有 JavaScript 那种直接改对象属性的习惯（字段是 `final` 的，
建好就不能改）。要改一个对象的值，先复制一份新的，只换要改的字段，
这就是 `copyWith`——项目里到处都是这个模式：

```dart
// lib/models/models.dart，CauseRecord.copyWith（节选）
CauseRecord copyWith({
  CauseStatus? status,
  int? solvedCount,
  DateTime? lastCheck,
  DateTime? recheckDate,
  List<String>? remedyHistory,
  DateTime? joinedAt,
  bool clearRecheckDate = false,
}) {
  return CauseRecord(
    questionId: questionId,
    cause: cause,
    subjectId: subjectId,
    status: status ?? this.status,   // 传了新值就用新值，没传就用旧值
    solvedCount: solvedCount ?? this.solvedCount,
    // ...
  );
}
```

用法就是：`r.copyWith(status: CauseStatus.solved, solvedCount: 2)`，
得到一个新对象，原对象不动。`??` 的意思是“左边是空就用右边”，见空安全一节。

花括号 `{...}` 里的参数叫**命名参数**，调用时必须写名字（`status: ...`），
顺序可以乱；没有花括号的参数叫位置参数，调用时按顺序传。
`copyWith` 里全是命名参数，所以调用时一眼能看出改了什么。

### Future / async / await（异步）

读数据库、读文件都是慢操作，Dart 用 `Future` 表示“以后才有结果”。
`async` 标在函数上表示它是异步的，`await` 表示“等结果回来再往下走”。
读库的代码基本都是这个样子：

```dart
// lib/modules/report/report_page.dart
Future<void> _load() async {
  final records = await widget.repo.causeRecords();
  final questions = await widget.repo.all(includeArchived: true);
  if (!mounted) return;   // 等回来时页面已经关了，就别再刷新了
  setState(() {
    _records = records;
    _questions = questions;
    _loading = false;
  });
}
```

- `Future<void>` 表示这个函数将来完成，但不返回有用的值。
- `await` 只能写在 `async` 函数里。
- `Future.wait([...])` 可以同时发起多个异步操作，等它们全部完成
  （首页 `_load` 就是这么一次并行读 5 样数据）。
- `if (!mounted) return;` 是固定习惯：异步等回来时页面可能已经关了，
  先判断再 `setState`，否则会报错。

### List / Map 常用操作

`List` 是列表（数组），`Map` 是键值对（字典）。项目里最常用的三个操作：

```dart
// lib/data/repository.dart，homeRevCounts()
// where：过滤；length：计数
map[s.id] = due.where((q) => q.subjectId == s.id).length;

// map：把每个元素换成另一个样子；toList()：把结果收成列表
final titles = questions.map((q) => q.title).toList();

// any：有没有一个满足条件；every：是不是全部满足
if (rs.any((r) => r.status != CauseStatus.solved)) toReview++;
if (rs.every((r) => r.status == CauseStatus.solved)) solved++;
```

`(q) => q.subjectId == s.id` 叫**箭头函数**（lambda），意思是
“给一个 q，返回它是不是这个学科的题”。`=>` 后面只能写一个表达式；
要写多行就用花括号 `{ ... }`。

`Map` 的字面量长这样（花括号里 `key: value`）：

```dart
// lib/data/database.dart，_toRow（节选）
static Map<String, Object?> _toRow(Question q) => {
      'id': q.id,
      'title': q.title,
      'subject_id': q.subjectId,
      'is_demo': q.isDemo ? 1 : 0,   // 三元表达式：条件 ? 真值 : 假值
    };
```

### switch 表达式

Dart 的 `switch` 可以当表达式用（直接产生一个值），项目里大量用它做映射。
注意最后的 `_` 是“其他所有情况”：

```dart
// lib/app.dart
ThemeMode get _themeMode => switch (_settings.themeMode) {
      'light' => ThemeMode.light,
      'dark' => ThemeMode.dark,
      _ => ThemeMode.system,
    };
```

```dart
// lib/models/models.dart，CauseStatusLabel
String get label => switch (this) {
      CauseStatus.pending => '待解决',
      CauseStatus.inProgress => '解决中',
      CauseStatus.solved => '已解决',
    };
```

还有一种写法是 `switch` 语句（不返回值，只执行分支），首页按最近任务跳转
用的就是它（`_resumeRecent`）。多个值共用一个分支时用 `||`：

```dart
// lib/modules/home/home_page.dart
String _normalizedKind(String kind) => switch (kind) {
      'organize' || '整理' => 'organize',
      'collect' || '收集' => 'collect',
      _ => 'review',
    };
```

### Widget 树

Flutter 的界面是一棵**组件树**（Widget 树）。每个界面元素都是一个 Widget，
Widget 里面套 Widget。`build` 方法就是“按现在的数据，把这棵树画出来”：

```dart
// lib/modules/home/home_page.dart，_HomePageState.build（节选）
@override
Widget build(BuildContext context) {
  return SingleChildScrollView(   // 可滚动的容器
    child: Column(                // 垂直排一列
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        Text(widget.settings.greeting, style: ...),  // 问候语
        SizedBox(height: 3 * scale),                // 空 3px
        Text('上次停在：...', style: ...),             // 副标题
        // ...焦点卡、四格
      ],
    ),
  );
}
```

读法：从外往里读。`SingleChildScrollView` 里面是 `Column`，
`Column` 的 `children` 列表里依次是问候语、间距、副标题……
布局组件（`Column` 垂直排、`Row` 水平排、`SizedBox` 占个空位、
`Padding` 留边）只负责位置，真正显示的东西是 `Text`、`Container`、
按钮这些叶子组件。

### StatelessWidget 与 StatefulWidget

两种组件，区别只有一个：**数据变了之后要不要重新画**。

- `StatelessWidget`（无状态）：画一次就定型，数据不变。例子是纸纹背景：

```dart
// lib/theme/app_theme.dart
class PaperDots extends StatelessWidget {
  const PaperDots({super.key});
  @override
  Widget build(BuildContext context) { ... }
}
```

- `StatefulWidget`（有状态）：数据会变，变了要重新画。所有页面都是这种。
  它拆成两部分：Widget 本身（只存传进来的参数）+ State（存会变的数据和逻辑）：

```dart
// lib/modules/home/home_page.dart
class HomePage extends StatefulWidget {
  const HomePage({super.key, required this.repo, ...});
  final QuestionRepository repo;   // 传进来的参数放这里
  @override
  State<HomePage> createState() => _HomePageState();
}

class _HomePageState extends State<HomePage> {
  Map<String, int>? _revCounts;   // 会变的数据放这里
  bool _loading = true;
  @override
  void initState() {
    super.initState();
    _load();                      // 页面第一次画出来之前，先去读数据
  }
  @override
  Widget build(BuildContext context) { ... }
}
```

下划线开头的类名（`_HomePageState`）表示**只在这个文件里用**，
出了这个文件就看不到。这是 Dart 的私有约定：下划线 = 文件私有。

### setState

数据变了要刷新界面，就调 `setState`，把改数据的代码包在里面。
调完后 Flutter 会重新执行 `build`，按新数据重画：

```dart
setState(() {
  _revCounts = results[0] as Map<String, int>;
  _loading = false;
});
```

只改数据、不调 `setState`，界面不会变；反过来，`setState` 里不要做
读库、网络这种耗时操作，只改内存里的数据。

### BuildContext 是什么

每个 `build` 方法都收到一个 `context` 参数。可以把它理解成
“这个组件在整棵树里的位置”。有了它才能问到离自己最近的主题、字号、导航器：

```dart
final palette = DesignTokens.of(Theme.of(context).brightness);
final scale = qmScaleOf(context);
```

`Theme.of(context)` 的意思是“从我这个位置往上找，最近的主题是什么”。
所以 `context` 不能乱传：想在某个回调里用 `context`，必须保证那个组件
还在树上（已经关掉的页面不能用，这就是前面 `if (!mounted) return` 的原因）。

### 空安全（`?` 与 `!`）基础

Dart 规定：一个变量要么一定有值，要么类型后面加 `?` 表示“可能为空”。
这叫空安全，编译器会帮你拦住“对空值调用方法”这类错误。

```dart
// lib/models/models.dart
final String? answer;      // 答案可能为空（没填）
final String? examId;      // 可能没挂试卷
final DateTime? lastCheck; // 可能还没自查过
```

三个配套写法：

- `??`：左边为空就用右边。`examId: examId ?? this.examId`
  （copyWith 里“没传新值就用旧值”就是靠它）。
- `?.`：左边为空就整个表达式为空，不报错。
  `r['last_check'] == null ? null : DateTime.fromMillisecondsSinceEpoch(...)`
  这种写法在数据库读数里很常见。
- `!`：告诉编译器“我确定这里不为空”。少用，只在确实能保证时用：

```dart
// lib/models/models.dart，CoverColors.of
static Color of(String key) => hex[key] ?? hex['blue']!;
```

`hex['blue']!` 的意思是：查表可能返回空，但我知道 `'blue'` 一定在表里，
所以强制取值。写 `!` 之前先想一想：万一真是空，程序会在这里崩掉。

类型转换的写法也常出现：`r['color'] as int?` 是把数据库读出来的值
当作“可能为空的整数”来用，`?? 0xFF2F7CF6` 再给个默认值。

## 6. 常见任务手册

每个任务写清改哪几处、按什么顺序。改完都按第 1 节的三步验证
（`flutter analyze` → `flutter test` → 跑起来看一遍）。

### 改一句文案

1. 在 `lib/` 里搜这句话（VS Code 里 Ctrl+Shift+F 全局搜索），找到所在文件。
   文案基本都在页面文件里直接写着，少数在 `models.dart`（如默认问候语）
   或 `home_page.dart` 的 `backupFailedMessage`。
2. 改文字，保存。
3. 跑 `flutter analyze` + `flutter test`，再跑起来看一眼。

注意：别改设计说明类的文字——按决定，设计说明不进应用；
也别把原型 HTML 里的说明文字抄进来。

### 改颜色 / 字号

**只改 `lib/theme/design_tokens.dart`**，不要在页面文件里写死色值。

- 改颜色：找到 `DesignTokens.light` 或 `DesignTokens.dark` 里对应的字段
  （如主色 `accent`、背景 `background`、正文 `ink`），改 `Color(0xFF......)` 的值。
  `0xFF` 后面 6 位就是十六进制颜色（和网页的 `#2E7CF6` 同一个意思，
  前面的 `FF` 是不透明）。
- 改字号：改 `DesignTokens` 里的基准字号常量（如 `bodyFontSize = 15`、
  `pageTitleFontSize = 24`）。字号只在这里改基准值，缩放（标准 1.00 /
  大 1.15 / 特大 1.30）由 `app.dart` 的 `MediaQuery TextScaler` 全局做一次，
  组件里不要再乘。
- 学科色和封面色是两套值：学科色用 `DesignTokens.subjectColor`，
  封面色用 `CoverTokens`（7 预设色），不要合并。

两个坑：

- `app_theme.dart` 里有一批 `AppTheme` 兼容常量（如 `AppTheme.accent`），
  值是照抄 `DesignTokens` 的字面值，改颜色时两处要同步（文件头注释里写了对照表）。
  新代码请直接用 `DesignTokens`，不要再加 `AppTheme` 常量。
- 字体只声明字体栈（`fontFamily = 'Segoe UI'`，回退 `Microsoft YaHei`），
  不打包字体文件。想换字体只改 `design_tokens.dart` 这一处；
  如果字体不在系统里，还要把 .ttf 文件放进项目并在 `pubspec.yaml` 声明，
  那会改动“不打包字体”的决定，改之前先定夺。

### 加一个设置项

以“加一个开关”为例，共三处：

1. **`lib/models/models.dart` 的 `AppSettings`**：加字段、默认值，
   再同步三处——`toMap()`（存）、`fromMap()`（读）、`copyWith()`（改）。
   值存在 `settings` 表里，都是字符串，布尔用 `'1'` / `'0'` 存
   （看 `redoAnswerHidden` 的现成写法）。
2. **`lib/modules/settings/settings_page.dart`**：在对应的组
   （外观 / 复习 / 错题本 / 数据 / 启动与关于）里加一行控件，
   改完调 `widget.onSettingsChanged(...)`（它会写库并刷新全应用）。
3. **用到的页面**：读 `widget.settings.新字段`（首页是构造时传进来的
   `settings`；复习页、报告页是在 `_load` 里 `await widget.repo.settings()` 现读的）。

### 加一页

按模块边界规矩，加一页要改 4 处（见 `docs/quiz-master2-mo-kuai-bian-jie-hua-fen.md`）：

1. **新文件**：`lib/modules/新目录/新页面.dart`，写一个 `StatefulWidget`，
   构造参数第一个就是 `required this.repo`，再按需加回调
   （`onGoXxx` 这种 `VoidCallback`）。
2. **`lib/app.dart` 的 `_buildPage()`**：在 `switch (_route)` 里加一个
   `case '/新路由':`，返回新页面。
3. **`lib/widgets/app_shell.dart` 的导航列表**：在 `_NavItemData` 列表里
   加一项（路由、名字、图标字、角标）。如果新页不进左导航（像题目详情），
   这步跳过，改用 `Navigator.push` 打开（照 `app.dart` 的 `_openDetail` 写）。
4. **需要时接线**：别的页面要能跳过来，就在 `app.dart` 加一个 `_goXxx` 方法；
   导航角标要变，就在数据写入口调 `bumpBadgeVersion()`
   （`lib/data/badge_notifier.dart`）。

### 数据库加字段（Schema 变更）

这是最要小心的操作，因为用户机器上的旧库也要能接着用。

1. `lib/data/database.dart` 里 `version: 1` 改成 `2`，并加上 `onUpgrade`
   回调（现在只有 `onCreate`，没有 `onUpgrade`，要新写）。
2. `onUpgrade` 里用 `ALTER TABLE 表名 ADD COLUMN 新列 类型` 加列，
   并给旧数据填默认值（新列最好都带 `DEFAULT`，否则旧行读出来是空）。
3. `_onCreate` 里新库建表时也加上这列（新装的用户走建表，不走升级）。
4. `_toRow` / `_fromRow` 里加上这个字段的存取。
5. `lib/models/models.dart` 对应模型类里加字段（`copyWith` 里也加上）。
6. 测试两种库：删掉本地库全新跑一遍（走 `_onCreate`），再拿一个旧版库
   升上来跑一遍（走 `onUpgrade`），两种都不能丢数据、不能崩。

注意：`cause_records` 的治愈口径（复查通过率等）是拿 `lastCheck` 近似算的，
真要精确需要加字段，这属于改 Schema，按上面流程走，不要偷偷加。

### 修一个 bug 的标准流程

1. **复现**：先在自己机器上把 bug 重现出来，记下页面、操作、期望和实际。
   能截图就截图，能像素采样就采样（导航变黑那个 bug 就是靠像素采样定位的）。
2. **定位**：按第 2 节的目录地图找到文件，再按第 4 节找到方法。
   先读方法上的注释——很多坑注释里已经写了（比如 `upsertSubject` 的
   REPLACE 会顶到表尾，就是靠注释 + 代码确认的）。
3. **改**：最小改动，只改出问题的地方，不要顺手重构周围代码，
   不要扩大范围（修学科排序就不要顺手把标签排序也改了）。
4. **测**：`flutter analyze` 0 问题；`flutter test` 全过；
   涉及界面的，跑起来按复现步骤再走一遍，截图留证。
   如果修的是回归问题，顺手在 `test/` 里加一个回归测试，
   断言修掉的现象不再出现（导航悬停那个 bug 就加了
   `test/nav_hover_regression_test.dart`）。
5. **记**：修完把原因、修法、验证写进 `docs/ui-replication/BUGFIX-日期.md`，
   再按负责人的决定 push（push 一定要先确认，不要自己推）。

### 常见报错及处理

- **`flutter` 命令找不到**：Flutter SDK 不在 PATH 里。去 SDK 目录
  （如 `D:\flutter\bin`）检查，或重开一个 PowerShell 再试。
- **报 `app_icon.ico` 缺失 / `Runner.rc` 报错**：检查
  `windows/runner/resources/app_icon.ico` 在不在；不在就从仓库里恢复，
  不要改 `Runner.rc`。
- **Windows 工程壳报错**：先试 `flutter create --platforms=windows .`
  重新生成 `windows/` 脚手架（`lib/` 不会被覆盖，这是 D-13 定好的办法）。
- **Linux 验证机上构建报 `gtk+-3.0` 找不到**：VM 换机后开发包丢了，
  `apt-get install` 可能因 libzstd 版本冲突装不上；用
  `apt-get download <包名>` + `dpkg-deb -x <包>.deb /` 补包
  （补过：`libgtk-3-dev`、`libgdk-pixbuf-2.0-dev`、`libtiff-dev`、
  `libzstd-dev`；注意 `libgdk-pixbuf2.0-dev` 不带横线的是个空壳，
  要用带横线的名字）。
- **`pubspec.lock` 不要手改**：它是依赖锁定文件，改依赖只改
  `pubspec.yaml` 然后跑 `flutter pub get`，让工具自己生成 lock。
  依赖升级需要负责人决定，不要顺手升级。
- **改完代码界面没变**：先确认是不是改错了文件（同名文件可能有多个，
  比如 `quiz-master2-F`、`quiz-master2-F2`、`quiz-master2-UI`
  是三个不同的目录）；再确认跑的是不是当前分支（`git branch` 看一眼）。

## 8. 哪里别碰

### 不要改 SQLite Schema（除非按第 6 节的流程走）

12 张表的结构、字段名、version 1 都不要随手改。用户机器上的旧库
要靠升级流程接着用；改了结构不写迁移，旧库会直接打不开。

### 不要改业务口径

这些是负责人定好的规则，改了就是改产品，不是改代码：

- 错因治愈规则：同一错因在同一道题上自查“已解决” 2 次才算治愈
  （`cureChecks` 默认 2，设置页可改 1/2/3，但规则本身别改）。
- 复查间隔默认 7 天（3/7/14 可选）；跳过两次留到下次；复查不过打回解决中。
- 要复习的题“数题不数错因”；首页焦点卡与导航速览同一口径。
- 本周 = 本周一到今天；文件夹按学科分、只一层子文件夹；一道题只存一份。
- 错题本默认不显示已掌握和已归档的题；收藏不加权排序。

想改口径先记进 `docs/decision-log.md`，等负责人定夺，不要直接改代码。

### YOLO 占位实现别当真

```dart
return [
```
